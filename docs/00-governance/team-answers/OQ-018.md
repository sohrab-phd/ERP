**OQ-018 — Architecture and Node.js Platform ADR Set**

**Decision:** Accept the Modular Monolith and PostgreSQL directions for the MVP. Keep framework/package and deployment-tool selections subject to explicit follow-up ADRs rather than treating popularity as an architectural requirement.

### Required constraints

The system must be maintainable by a small engineering team.

Development must be practical on Windows workstations, while production must support a Linux-based deployment environment.

The application must not require Windows Server as a production dependency.

The first-go-live architecture should support on-premises deployment and should not require a specific cloud provider or managed cloud service.

External infrastructure dependencies should remain minimal and must have an explicit business or technical justification before being introduced.

Distributed-system infrastructure such as Kubernetes, Kafka, RabbitMQ, Redis, or service-per-domain deployment is not required for MVP unless an evidence-based requirement is subsequently approved.

### Architecture style

**Accept ADR-0006 direction: Modular Monolith.**

The ERP is implemented as a single deployable application containing strongly bounded business modules.

Modules must have explicit ownership boundaries and must not bypass domain/application contracts through uncontrolled cross-module database access.

The architecture must preserve the existing one-writer Inventory Ledger model.

### Data platform

**Accept ADR-0007 direction: PostgreSQL as the transactional System of Record.**

PostgreSQL owns durable transactional business facts, including the authoritative Inventory Ledger.

The application/domain layer owns business orchestration, while PostgreSQL provides transactional atomicity, constraints, locking, and integrity enforcement.

ORM abstractions must not become a second Inventory posting writer.

### Backend language/runtime

The backend language/runtime baseline remains:

**Node.js + TypeScript**

The previous .NET / ASP.NET Core / C# baseline is superseded and must not be reintroduced.

### Framework selection

NestJS is a strong candidate for the Node.js/TypeScript application framework and is compatible with the Modular Monolith direction, but the framework selection should be recorded as a dedicated technology ADR after the relevant implementation/design spike.

The architecture must not treat framework popularity alone as sufficient evidence.

### Data-access technology

Prisma may be evaluated as the primary data-access abstraction, with controlled raw SQL where required by transactional/concurrency behavior.

Prisma must not become the authoritative Inventory posting kernel.

The final ORM/data-access decision must be recorded in the relevant technology ADR.

### Authentication and authorization packages

No specific authentication/authorization package is frozen by this OQ.

The implementation must preserve the existing security requirements, including session security, RBAC/policy enforcement, customer isolation, auditability, and separation of duties.

The concrete package choice requires a dedicated ADR/evaluation.

### Frontend and real-time technologies

React/TypeScript and Socket.IO remain candidate technologies consistent with the overall architecture, but this OQ does not independently freeze their package versions.

Their final versions and package choices must be recorded in the corresponding technology decisions.

### Deployment

Do not freeze a specific Docker Compose/Nginx/host topology through OQ-018.

The deployment architecture must be finalized after the operational hosting constraints and recovery requirements are reconciled.

The implementation must remain compatible with Linux-based production deployment.

### Testing

No specific test runner is frozen by this OQ.

The project must retain the approved testing principles and select the concrete TypeScript test tooling through an explicit technology decision.

### Extra MCP

**Extra MCP: None by default.**

Additional MCP servers may be introduced only when a concrete project capability requires them and the server has an identified purpose, security boundary, and maintenance owner.

### Architectural principle

> Freeze architectural decisions where the project has sufficient evidence; defer framework, package, and infrastructure details to explicit technology ADRs rather than allowing tools to become architecture by accident.

**Status:** Modular Monolith and PostgreSQL directions accepted. Node.js + TypeScript remains the backend baseline. NestJS, Prisma, React, Socket.IO, test runner, authentication packages, Docker Compose topology, and additional MCP remain subject to explicit technology ADRs.
