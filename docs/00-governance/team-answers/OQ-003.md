**OQ-003 — Production Routing and Posting Points**

**Decision:** Production routing is product-line-specific and must be represented by an approved, versioned routing definition. The system must not hard-code or assume a universal manufacturing route.

For the first go-live, the actual routing steps will be established in the approved routing catalogue for each product line. Until that catalogue is provided, no specific shop-floor step names are treated as authoritative. The later clarification in this file records ten current physical Stations. Those names are current factory evidence. They are not a permanent catalogue and not a mandatory sequence. The sentence above is the earlier baseline, before those names were supplied.

### Official consumption and output point

The authoritative production posting point is:

**`CompleteProductionOperation`**

At completion of an operation, the following are posted as one indivisible business transaction:

1. Actual material consumption
2. Good production output
3. Residual material, where applicable
4. Scrap, where applicable

Consumption must not be posted independently from the corresponding output/residual/scrap result.

The transaction must succeed or fail as a single business operation.

### Optional / skippable operations

An operation is skippable only when the approved routing version explicitly marks it as optional/skippable.

There is no implicit step skipping.

If completion or progression requires a step that has not been completed and no approved skip rule exists, the operation is rejected with the appropriate `GUARD_OPEN_POLICY`.

### Abort

A Production Order that has not produced any posted inventory facts may be aborted according to the normal Production authorization policy.

After inventory-affecting production postings have occurred, abort requires an authorized production-supervisor/production-manager role and must use controlled compensating/reversal transactions. Existing inventory ledger facts and audit history must never be deleted or silently rewritten.

The exact role name will be finalized in the authorization/RACI decision set.

### Routing model

Each production routing must be versioned and associated with the applicable product/product family. A routing version may define:

- operation sequence
- operation name/type
- work center or machine
- required inputs
- expected outputs
- quality requirements
- measurement requirements
- optional/skippable status
- completion/posting requirements

The system must preserve the routing version used by each Production Order so that historical production records remain reproducible.

### Architectural invariant

> `CompleteProductionOperation` is the authoritative atomic posting boundary for production consumption and production results. Consumption, good output, residual, and scrap are not independent inventory postings.

**Status:** Architectural baseline accepted. Actual first-go-live routing step names and approved abort authority remain controlled business/process inputs.
