**OQ-011 — Weighbridge Integration**

**Decision:** The weighbridge is an evidence/command source only. It must never write directly to the Inventory Ledger.

### Device

The exact weighbridge make, model, location, and communication protocol are not yet confirmed and must not be invented by the architecture.

Until the physical device and its protocol are documented, automatic integration remains behind `GUARD_OPEN_POLICY` / `SPIKE-DEVICE`.

### Integration path

When an approved weighbridge integration exists, the flow is:

**Weighbridge → Adapter → validated weight evidence/command → `PostGoodsReceipt` → Inventory posting**

The Adapter must not bypass the Goods Receipt business command and must not directly write Inventory Ledger records.

The existing `WI-BUNDLE-GR` transaction remains the authoritative Goods Receipt posting boundary.

### Duplicate prevention

Automatic weighbridge submissions must contain a stable external evidence identifier supplied by the device/protocol, such as a weighbridge ticket/transaction identifier.

That identifier must participate in idempotency/duplicate detection so that replaying the same weighbridge evidence cannot create a second Goods Receipt posting.

If the physical device does not provide a suitable stable identifier, a device-specific idempotency strategy must be defined during the integration spike. The architecture must not invent a fake device identifier.

### Device-down / unavailable fallback

The first-go-live fallback is **human posting from the printed weighbridge ticket**.

An authorized user records the ticket information and invokes the **same `PostGoodsReceipt` business command** used by the automatic path.

The fallback must not create a separate inventory-posting implementation.

### Trust rule

The printed ticket or automated device evidence is evidence for the transaction. The Inventory Ledger remains owned and posted by the Inventory posting authority.

### Operational roles

The exact human role responsible for manual ticket entry must be confirmed through the operational RACI. Until then, the architecture should refer to an **authorized Goods Receipt operator**, not invent a person's name.

### Architectural principle

> Weighbridge integration provides trusted weight evidence; it does not own Inventory posting. Automatic and manual paths converge on the same Goods Receipt business transaction.

**Status:** Architectural trust and fallback policy accepted. Device make/model, communication protocol, stable device identifier, and named operational role remain open until the physical integration details are supplied.
