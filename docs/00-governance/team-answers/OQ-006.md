**OQ-006 — Fulfillment Tolerances**

**Decision:** Partial fulfillment is supported, while under-delivery, over-delivery, and production over-output are governed by explicit configurable tolerances. No universal tolerance percentage is hard-coded.

### Partial shipment

Partial shipment is permitted where the Sales Order or Sales Order Line explicitly allows partial fulfillment.

A Sales Order Line may therefore be fulfilled through multiple shipments.

Each shipment must retain its own quantity, inventory references, quality eligibility, and traceability information.

The original ordered quantity must remain immutable.

### Under-delivery

Under-delivery is not permitted by default.

A Sales Order Line may define an explicit under-delivery tolerance using either:

- percentage tolerance, or
- absolute quantity tolerance.

If no tolerance is defined, the acceptable under-delivery tolerance is zero.

### Over-delivery

Over-delivery is not permitted by default.

A Sales Order Line may define an explicit over-delivery tolerance using either:

- percentage tolerance, or
- absolute quantity tolerance.

If no tolerance is defined, the acceptable over-delivery tolerance is zero.

Any shipment exceeding the configured tolerance must require an explicit authorized exception decision.

### Production over-output

Production output exceeding the Production Order target is not automatically accepted.

A Production Order or applicable Product/Production Policy may define an explicit over-production tolerance.

If no tolerance exists, output above the target quantity must be treated as an exception requiring an authorized decision.

### Tolerance representation

The system must support both:

- **Percentage tolerance**
- **Absolute quantity tolerance**

The effective tolerance applied to a transaction must be deterministically calculated and recorded for auditability.

### Immutable quantities

Tolerance handling must never modify the original ordered or planned quantities.

For example:

- Ordered: 1,000 kg
- Shipped: 1,012 kg
- Allowed over-delivery: 2%
- Result: Accepted within tolerance

The system retains all four facts rather than changing the ordered quantity to 1,012 kg.

### Exception handling

A quantity outside the configured tolerance must not be bypassed through an ordinary UI action.

The exception must:

1. be explicitly identified,
2. require the appropriate authorization,
3. record the reason and decision maker,
4. remain auditable.

### Architectural principle

> Tolerances are explicit business policies, not hidden global constants. In the absence of an applicable tolerance policy, the default tolerance is zero.

**Status:** Accepted as the architectural baseline. Exact tolerance values by product/customer/order type remain controlled business inputs.
